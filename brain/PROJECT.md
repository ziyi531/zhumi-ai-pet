# 团子 · 项目总览（核心设定 + 进度）

> 新对话从这里接上。细节看各自的 README / PROTOCOL.md。最后更新：2026-10-19。

## 1. 产品定位

现实里存在的**便携式 AI 宠物**，主打**情绪价值**和**主动交互**（“逆向 Agent”：它有内在状态，会自己来找你）。
- **身体**：ESP32-S3 设备，负责表情、触摸、收音放音、本地本能（眨眼、摸头反应、睡觉、断线时想你）。
- **大脑**：家里 PC，负责对话（Ollama **Qwen3.5-9B** 纯文字版，2026-10-19 从 Qwen2.5-7B 换来）、记忆、内在状态、主动搭话、语音识别、语音合成。PC 大部分时间开机。
- **原则**：全部本地、隐私不外流；**数值和决定都在代码里，LLM 只负责措辞**。例外是用户要的**小工具**：上网查只发搜索词、天气只发城市名、问云端（Gemini）只发一句改写过的问题，主人的称呼都会先抹掉，对话、记忆、画像都不外传；各自都能关（`PET_WEB_SEARCH` / `PET_WEATHER` / `PET_CLOUD`）。

## 2. 核心设定

- **名字**：猪咪（2026-10-26 由“团子”改名；人设里告诉它以前叫团子，旧记忆里的“团子”就是它。`config.PET_NAME` / `PET_OLD_NAMES`）。唤醒词“Hi，喵喵”（“猪咪猪咪”用命令词识别实测认不准，见固件 README），也可以按住屏幕说话。改名后它会照着旧聊天记录自称团子：喂给模型的历史里它自己的话换成新名字、回复里自称旧名字由代码换掉（主人问起或它在讲以前的名字时不换）。项目代号、代码注释里仍叫“团子”。
- **唤醒应答**：叫醒后随机应一句“在呢～”“怎么啦？”…（猪咪的声音，提前合成好嵌在固件里，`tools/make_wake_acks.py`），离线也能应。这也是离线语音包的第一步。
- **连续对话**：叫醒一次聊多轮，说完接着听；没人接话 6 秒、主人道别（代码判断，`say.end`）、或者只听到杂音（“.”“The.” 当没听清）就结束。寄居在电路板里的小灵体，黏人、好奇、偶尔傲娇，每次 1~3 句话，从不自称 AI。
- **内在状态**（纯函数，由时间戳推导）：精力（生物钟）、孤单（4 小时不理 ≈ 0.8，摸头会降）、好奇。
- **主动搭话规则**：回访 > 孤单 > 好奇；免打扰 23:30~08:30；两次主动至少隔 2 小时，被无视则翻倍；每天最多 4 次；摸头算回应。
- **记忆**（目标是“像同一个它”，不只是读日记）：
  - 回访：对话后提炼（如下午说眼睛酸 → 晚上 22:00 关心），到期时间由代码校验。
  - **情景记忆**（`recall.py`）：每件值得记的事一条（主人的事 / 你们之间 / 团子自己），用本地 bge-m3（强制 CPU）算向量；聊天时**按线索自动想起**最相关的 ≤3 条放进提示词（相关度 ≥0.6 + 同一个具体词加分），同一件事再提起就合并。
  - **慢慢长成的性格**（`traits.py`，纯函数）：亲密、信任、黏人、傲娇、活泼 5 个数，被聊天、摸头、被逗/夸/关心/听心事、被冷落一点点推动；每天每项最多变 0.04，黏人/傲娇/活泼每天回落 3% 往天生值靠，没见面的日子亲密慢慢降。数值由代码翻译成一句“你们这阵子的相处”给大脑。
  - **夜间整理**（`nightly.py`，免打扰时段每晚一次，`POST /api/nightly` 可手动触发）：
    相似度 ≥0.82 的同类记忆由代码列为候选、模型判断是不是同一件事，是就合成一句（变化写进去：“妈妈先住院，现已出院”）；
    按遗忘曲线淡忘记不清的小事（3 级半衰期 14 天，越常提起越牢，5 级永不忘；淡忘不删，再提起会“重新想起来”）；
    写团子第一人称日记，“今天最想记住的事”存成一条往事；在昨天的基础上小小修订“我是怎样的团子”，放进每次聊天的提示词。
  - 日记不会每次聊天整篇读一遍（避免“扮演昨天的自己”）：连贯感靠被线索勾起的往事 + 慢慢长成的性格数值 + 自我认识。
  - **记忆管理页**（`/memory`，`memory_admin.py`）：看、改、删记忆（改文字会重算向量），看日记、画像、待回访的事，手动调性格数值和自我认识，“现在整理一次”，导出完整备份（JSON，不含向量）。删除都是真删。
  - **“忘掉这件事”**：对团子说“把……忘掉 / 别记着”，代码找出最相关的 ≤3 条记忆真删，取消相关回访，连原话一起删；只说“忘掉这件事”就指主人上一句。“你是不是忘了…”这类问句不算。团子会答应下来，聊天记录里只留“（主人让团子忘掉了一件事）”。
- **联网（工具调用）**：主人问到新游戏、新闻、人物、价格等不确定的事，团子先上网查再用自己的口吻答（比如“三角洲”会说出地理和《三角洲行动》两个意思再问是哪个）；闲聊不查。设备上显示“上网查「…」中”，回答下注明查了什么。只在对话时查，主动搭话不查。
- **云端代答**（2026-10-26 定）：服务开着、Ollama 没开时，由 Gemini 照同一套人设代答（主人同意发人设、最近 6 句、画像、按关键词勾起的记忆）。不用工具；当场提炼不了记忆，先攒着，本地大脑回来后按当时的时间补记（`memory.defer` / `memory.catch_up`）；网页注明“云端代答”。
- **心事**：主人吐露的秘密、害怕的、在意的事，提炼时一定记成 owner 记忆，重要度至少 4。电脑整台关机的情况很少，离线语音包先不做。
- **深夜**：01:00 后说话犯困、催睡觉，用“犯困”音色。
- **表情风格（已定）**：**呆猫·八条风**——银渐层小灰猫，圆头、平滑粗黑描边、超大黑眼加细黄绿虹膜圈，表情上方配大字（“嗯？”“哼！”“好困”）。12 个表情：idle listen think happy shy pout sad lonely curious sleepy sleep peek。参考了他人 IP，仅自用。
- **用户审美偏好**：不要宽扁/方的头型，不要手绘抖动线条；嫌 Kokoro 这类传统 TTS 太机械。

## 6. 下一步

**团子的声音（已定，2026-10-19）**：Qwen3-TTS（Apache-2.0；调研时备选 IndexTTS-2.5 情绪最强但要 6GB、GPT-SoVITS 最轻但不能控情绪）。
- **音色“小仓鼠”**：1.7B VoiceDesign 按描述捏（种子 1234，不克隆真人），描述和来历写在 `voice/voice.json`。
- **说话方式（用户反馈）**：每种情绪各“演”一段参考音像朗读课文，起伏太大 → 只用一段平常语气的参考音（WSOLA 不变调放慢到 85%）克隆，情绪只加一句很淡的 instruct，采样温度 0.75，语速比最初慢约 4%。情绪由代码按表情选（happy/shy→开心，pout→傲娇，sad/lonely→委屈，sleepy/深夜→犯困，其余→平常）。
- **实测（4060 8GB）**：声音服务常驻约 2.5GB，和大脑一起放在显卡上不溢出（见显存账）；回复到达后约 0.4 秒开口，合成速度约是说话的两倍。

- Qwen3-TTS 用独立环境 `.venv-fastq`（装法见 README 和 `requirements-tts.txt`），**必须锁 transformers==5.15.1**，5.20 会报 `MimiConfig has no rope_theta`。（官方 qwen-tts 的环境 `.venv-tts` 和 Kokoro 模型已于 2026-10-19 删除。）捏声音前要让 Ollama 卸掉大脑（1.7B 和 9B 放不进同一张卡）。“SoX could not be found”是无害警告。
- **显存是硬约束**：8GB 卡上声音服务 + 大脑要一起放下，靠两件事：`tts_service.py` 把 3.1 亿参数的文字词表放 CPU（省 0.6GB）；9B 只放一部分层进显卡。**层数不能写死**：Windows 桌面（dwm）的显存会慢慢涨（实测 200MB → 744MB），固定 28 层后来也溢出、大脑卡死过；现在 `NUM_GPU="fit"`，每次加载模型前按此刻空余现算（`llm.fit_layers`，参数在 `config.GPU_FIT`，留 400MB 余量），桌面 744MB 时算出约 26 层。对话最多等 120 秒（`REQUEST_TIMEOUT`），卡住就说“脑袋转不动了”，不让主人干等。超了不会报错，而是 Windows 在两个进程之间来回搬显存：声音头一句变慢，严重时 Ollama 卡到 100% 占用、几分钟出不来一句（2.5-7B 和 3.5-9B 带视觉版都实测踩过）。查溢出：`Get-Counter "\GPU Process Memory(*)\Dedicated Usage"` 看声音服务（python）是否还有约 2.5GB，被挤掉就是超了；llama-server 的 Shared Usage 里有一部分是正常的主机缓冲（9B 约 1.3GB），不全是溢出。改模型/层数后用交替压力测试（大脑一句、声音一句来回几轮）确认。
- **声音服务压显存试过，不划算（2026-10-25）**：GGUF/qwentts.cpp 后端没有 Windows 版（只有 Linux/macOS），自己编译要装 CUDA Toolkit + VS；在 PyTorch 里自己做 8bit 权重反而 2674→2770MB、RTF 0.60→0.97（加速库初始化时引用着原 bf16 权重，释放不掉）；编码器挪 CPU 只省 50MB。2.5GB 里约 0.7GB 是 CUDA Graph 的预分配空间，加速靠它。结论：留着现状，靠 `NUM_GPU="fit"` 给大脑自动让位。
- 台词里的“……”会让 Qwen3-TTS 偶尔跑飞或结尾拖几秒静音：服务里按字数限 `max_new_tokens`、超长截断、静音门（去首尾静音、句中停顿最多 0.5 秒）。
- 声音服务由大脑用 `.venv-fastq\Scripts\python.exe` 拉起；venv 的 python.exe 是个转发器，真正干活的是它的子进程（Python311\python.exe），关掉转发器子进程也会跟着退出（实测）。日志在 `data/tts_service.log`。
- 浏览器会缓存 `pet.html`，改完要强制刷新（或加 `?v=` 参数）才能看到新版。
- **Windows 上别用 `localhost` 连 Ollama**：会先试 IPv6 `::1`，Ollama 只听 IPv4，每次请求白等 2 秒（实测 2.08s vs 0.03s）。`OLLAMA_URL` 默认已改成 `127.0.0.1`；之前团子每句话都多等了这 2 秒。`bill_analyzer` 也是 `localhost`，同样受影响。
- **工具调用两种写法看模型**（`config.TOOL_MODE`）：qwen3.5 用 Ollama 原生 `tools`（10/10）；qwen2.5:7b 配原生 tools 一次都调不成（把调用写进正文、格式坏、冒乱码），只能用 JSON 动作（format=json 下输出 `{"search": "..."}` 或 `{"reply","face"}`）。查一次就够（`MAX_SEARCHES=1`）。
- **联网提示词很敏感**：写“问今天的事要带年月”会让 qwen3.5 一听主人说“今天/刚刚”就去搜新闻；写“一个词有几个意思就都说”会让它编出“地理上的悟空”。现在的写法是：只在问外面世界的事实时查，主人说自己的事和心情绝对不查；资料里确实有几样完全不同的东西才反问。
- **对话在后台任务里跑**（`link.py` 的 `hub.spawn(do_chat…)`）：以前接收循环会一直等大脑回完，冷启动加载 9B 要近一分钟，这期间 uvicorn 的心跳回应没人读，四五十秒就把网页的连接断了（显示“没连上大脑”）。同一台设备的对话用 `Client.turns` 锁排队。自测 `test_chat_does_not_block_socket` 盯着这个。
- **工具只在主人提问/请它办事时才给**（`brain.wants_tools`，看“吗/什么/几/多少/帮我/算/查/X不X”等）：工具一多，9B 听到“我中午吃了火锅”也会去搜网页、算日子，提示词压不住，改由代码决定。
- 农历节日（春节、中秋……）每年日期不同，9B 会瞎猜，必须走 `date_calc(holiday=…)` 由代码算。
- 原生 tools 模式下回答没有 JSON 约束，偶尔用中文引号把 JSON 写坏：`brain._salvage` 把 reply/face 抠出来，别把半截 JSON 念出来。
- Gemini：Google AI Pro 订阅不含 API；API 免费层的提问会被拿去训练（用户目前用免费层，只发一般性问题），开 Cloud 结算用付费层就不会（套餐每月 Cloud 额度可抵）。免费层上 `gemini-3.8-flash` 一次要 60~75 秒，`gemini-3.5-flash-lite` 约 5 秒，所以默认用后者。
- **白天即时合并门槛 0.92，不是 0.88**：“妈妈住院了”和“妈妈出院了”相似度 0.89，0.88 会把住院覆盖掉；说法差得多的同一件事留给夜间整理由模型判断。
- 提炼记忆时要把这轮勾起的往事一起给整理员看：否则“小糯米！我妈出院了”会被记成“猫咪小糯米……”（不知道小糯米是团子的外号）。
- **记忆阈值是实测校准的**（bge-m3）：同一件事换个说法 0.90~0.93、不同的事 0.70~0.77；相关问法 0.50~0.78、不相关闲聊最高也到 0.58 → 想起门槛 0.6，再给同一个具体词（咪咪、日本）加 0.08。短名字在向量里信息少，光靠向量会漏。
- 提炼记忆时要求“只记发生了什么，不记团子当时嘴硬的反应”：否则会记成“团子不喜欢小糯米这个外号”，以后一直排斥。需要回访的事也同时存一份往事。
- 9B 对 ask_cloud 也会“嘴上说去问问云端、手上不调”：和上网查一样提醒一次（`brain.SAYS_WILL`）。
- 定时提醒（2026-10-28）：真机上让它“30 秒后提醒我上厕所”，它答应了却没有这个能力，被记忆整理员记成回访、还推到了第二天（回访按 15 分钟心跳、30 分钟内的顺延一天）。现在有 `set_reminder` 工具和 `reminders` 表，pusher 每秒查，到点用固定句式出声，不受免打扰/冷却/每日上限；答应了没调同样提醒一次。
- 9B 偶尔嘴上说“我去查查看”却不调工具：`brain.py` 发现回复里有“查查/去查/搜一下”且这轮没查过，就提醒一次让它真去查（`SAYS_WILL_SEARCH`）。
- 支持思考的模型（qwen3.5）要传 `think: false`，否则先想一大段、慢好几倍；不支持的（qwen2.5）传了会报错，所以 `llm.py` 先查 `/api/show` 的 capabilities。
- 查资料的回答会聊到“人工智能”“语言模型”（比如问 DeepSeek），出戏检测此时只拦“我是 AI”这类自称（`config.SELF_AI_WORDS`），否则会被误判换成兜底话。
