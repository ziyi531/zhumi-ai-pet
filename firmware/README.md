# 团子固件（ai_pet_fw）

立创实战派 ESP32-S3 成品机上的“身体”。PC 端的“大脑”在 `C:\Users\76012\claude code\ai_pet\`。

> ESP-IDF 不支持带空格的路径，所以固件工程放在 `C:\Users\76012\esp\` 下，不和 `ai_pet` 放一起。

## 编译和烧录

在桌面的“ESP-IDF v6.1 PowerShell”里（或先运行 `. C:\Espressif\tools\Microsoft.v6.1.PowerShell_profile.ps1`）：

```
cd C:\Users\76012\esp\ai_pet_fw
$env:PYTHONUTF8 = "1"            # sdkconfig 里有中文（自定义唤醒词的显示名），esp-sr 打包模型的脚本默认按 GBK 读会报错
idf.py build
idf.py -p COM5 flash monitor     # COM 口在设备管理器里看
```

第一次烧录会把唤醒词模型（model 分区）一起写进去。

## 现在能做什么

- 屏幕显示八条风表情：待机眨眼、东张西望、呼吸起伏；摸屏幕会开心并冒爱心（睡着时被摸会犯困）。
- **唤醒词“Hi，喵喵”**（2026-10-26）：乐鑫训练好的 WakeNet `wn9_himiaomiao_tts`（menuconfig → ESP Speech Recognition 里选）。实测一喊就醒。
  - 试过“猪咪猪咪”：用命令词识别 MultiNet（mn7_cn）当唤醒词，拼音写在 sdkconfig，不用训练。真机五次只认出一次左右——MultiNet 按 3~6 秒一个窗口清空重来，唤醒词跨窗口就丢；调过送入音量（放大 4 倍时大声喊会截平）、窗口长度、门槛都不行。代码留在 `xiaozhi_audio/wake_words/custom_wake_word.cc`（改自小智，去掉了资源系统和唤醒词录音上传），选上 mn7_cn 就会自动用它。
  - MultiNet 很吃 CPU（一个核的三成多）：原来的 3 级优先级比画表情低，表情一费劲它就跟不上，AFE 缓冲区满、唤醒失灵，还刷屏警告拖垮联网。现在 AFE 处理任务 5 级、表情 2 级，AFE 的警告只留错误（WakeNet 下也保留这些设置）。
- **唤醒应答**：叫醒后马上随机应一句“在呢～”“怎么啦？”“嗯？”“我在呢。”（猪咪的声音，提前合成好嵌在固件里，`main/assets/wake_ack_*.ogg`，`ai_pet/tools/make_wake_acks.py` 重新生成），应完再开始听，不会把自己的声音录进去；不等大脑，没连上大脑时也会应。猪咪说话、思考时被叫醒、按住说话、连续对话接着听时不应。
- **按住屏幕说话**：按住超过 0.7 秒开始听，松手交给大脑（最长 12 秒）。轻点一下还是摸头；猪咪说话时按住就先闭嘴再听。唤醒词在喇叭响着、周围吵的时候靠不住，这个最准。
- **连续对话**：唤醒后聊完一句，猪咪说完会竖起耳朵接着听（不用再喊唤醒词），6 秒没接话、或者主人道别（“拜拜”“晚安”“我去忙了”……大脑判断，`say` 带 `end`）、或者听到的只是杂音（大脑把“.”“The.”这种识别结果当没听清）就结束，回去等唤醒词。主动搭话说完也会接着听。实测：叫醒后连聊四轮，说“拜拜”就停。
- **对着它聊天**（连着大脑时）：说唤醒词 → 倾听，录音编成 Opus（16kHz、60ms 一包）边录边发给大脑 → 说过话之后停顿 1.2 秒算说完（5 秒没开口取消，最长 12 秒）→ 思考 → 大脑用团子的声音回答（Opus 24kHz 推过来，直接进小智的解码队列播放）→ 播完回去等唤醒。
  判断“说完了”踩过的坑：唤醒后头 0.5 秒不算（“小智”尾音会被当成开口，主人一停顿就被当成说完，0.7 秒时截断过）；
  短于 0.2 秒的声响不算开口、也不打断停顿计时（环境小声响让停顿一直凑不满，录满过 12 秒）。每 0.1 秒查一次人声检测状态，不靠开口/闭口事件。
  真机实测（2026-10-26）：说完到识别出文字约 0.3 秒，识别后约 2 秒开口（大脑冷启动第一句要 8 秒加载模型）。
- **团子说话时摸摸头，它马上闭嘴**（清掉还没播的声音，发 `hush` 让大脑别再推），实测立刻停。
- “鹦鹉学舌”自检（没连上大脑时）：说“你好小智” → 倾听 3 秒并录音 → 思考 → 播放刚才录到的话。用来验证麦克风、喇叭、唤醒词、回声消除。
- 连 WiFi 和 PC 大脑（WebSocket，协议见 `ai_pet/PROTOCOL.md`）：基础表情跟着大脑的状态走（犯困、睡着、孤单），摸头上报，大脑主动来找你时探头（主动搭话也带声音）。
  先在 `idf.py menuconfig` → AI Pet 里填 WiFi 名、密码和大脑地址（`ws://<PC 局域网 IP>:8600/ws`），PC 上用 `--host 0.0.0.0` 启动服务。
  - 真机已连通（2026-10-26）：家里路由器是 `<home-wifi-2.4G>`（只能连 2.4GHz；不带后缀的 `<home-wifi>` 和 `_MLO` 板子连不上或看不到），大脑地址 `ws://<pc-lan-ip>:8600/ws`，板子拿到 `<board-lan-ip>`。电脑的 IP 是路由器分的，变了要改这里重烧（以后在路由器里给电脑固定 IP）。
  - 开机会先扫一遍周围的 2.4GHz WiFi 打到日志里；连不上时日志有原因码（201 找不到网络，15/204 密码不对）。
  - 摸头、离线期间攒下的摸头，连上后都会报给大脑（实测离线摸 3 下，重连后补报一条 count=3）。大脑的对话回复只发给发问的设备，主动搭话和状态才推给所有设备。
  - 重启大脑：大脑正常关闭会先发“关闭连接”，esp_websocket_client 收到后**不会**自动重连（只有突然断线才会）。
    现在收到 `WEBSOCKET_EVENT_CLOSED` 就由 `link_switch` 任务等 2 秒自己重连，实测重启大脑后约 5 秒连回来。
    以前没修时板子一直离线，喊唤醒词只会“鹦鹉学舌”放出主人自己的声音；现在没连上大脑时喊唤醒词只歪歪头（学舌自检留着，`kParrotSelfTest`）。
  - 两个 WiFi：家里（`CONFIG_PET_WIFI_SSID`）和手机热点（`CONFIG_PET_WIFI2_SSID`，现在是 `<phone-hotspot>`，热点要开 2.4GHz）。
    开机扫一遍，哪个在连哪个，都在时连家里；连着的不见了（原因 201，或同一个连不上 3 次）就重新扫、换另一个。
    连家里的走局域网，连热点的直接走服务器中转。实测（2026-10-27）：连热点开机约 9 秒在线，说完到识别 0.9 秒、再到开口 3.1 秒。
  - 出门在外：局域网地址连续 2 次连不上，就换 `CONFIG_PET_SERVER_URL_REMOTE`（`wss://your-domain.example:443/pet/ws`，经 Lightsail 中转，用内置根证书校验；端口必须写明，见 Kconfig 说明），那个也连不上再换回来；hello 带 `CONFIG_PET_DEVICE_TOKEN`。换地址在单独的 `link_switch` 任务里做（websocket 事件回调里不能 stop 客户端）。
  - `sdkconfig` 里有 WiFi 密码和设备密钥，这个目录不是 git 仓库；以后要放进 git，先把 `sdkconfig` 加进 `.gitignore`。
- 串口日志每 100 帧打印一次平均渲染耗时（`avg render N ms/frame`）。真机实测约 22ms/帧（目标 50ms，20 帧/秒）。
  - 第一次上真机是 468ms/帧（约 2 帧/秒）。原因是光栅器对每个形状包围盒里的每个像素都算一遍距离，头和耳朵占了八成。
  - 改法（画面不变）：`std::hypot` 换成 `sqrtf`；按距离跳过形状外的像素，形状里面整段直接写；多边形的边预先算好；
    整个头（耳朵、渐变、肚皮、描边）画进缓存，每帧整块拷贝，只在耳朵姿势变了时重画（`bajo_face.cc` 的头部缓存，占约 1.2MB PSRAM）。
- 声音（真机实测，鹦鹉学舌已通）：
  - 只插 USB 时，音量 70 一响，大电流会把板子拉到掉电重启（日志里出现 `rst:0x1 (POWERON)`）。改成开喇叭时先开功放、等 30ms 再让 ES8311 出声（`lichuang_board.cc` 的 `PetAudioCodec`），默认音量 65（50 太小，65 实测不掉电）。
  - 麦克风增益 28dB 时，30cm 外说话录到的 RMS 只有 60~300（喇叭正常播放约 5000），改成 ES7210 的最大值 37.5dB；鹦鹉学舌回放再数字放大 4 倍（`audio_service.cc` 的 `testing_replay_gain_`，只在自检回放时生效）。
  - 串口：日志走 CH340K（COM4）和 S3 自带 USB（COM3）两路；烧录用 COM3。用 pyserial 读 COM4 时要先把 DTR/RTS 设成 False，不然板子一直卡在复位。

## 结构

| 目录 | 内容 |
|---|---|
| `main/main.cc` | 入口和状态机 |
| `main/net/` | WiFi 和 WebSocket 客户端 `pet_link`，和网页团子同一套协议 |
| `main/board/` | 板级初始化：I2C、PCA9557 扩展 IO、ST7789 屏幕、FT5x06 触摸、背光、音频编解码芯片 |
| `main/face/` | 表情：`face_anim` 参数和插值、`canvas` 抗锯齿软件光栅器、`bajo_face` 八条风画法、`face_display` 显示任务、`captions.h` 预渲染大字 |
| `main/xiaozhi_audio/` | 从小智固件拿来的语音模块（见下） |
| `tools/gen_captions.py` | 重新生成表情上方的大字 |

表情的数值和画法与网页预览 `ai_pet/static/faces.html` 的 `bajo` 风格一一对应，改表情时两边一起改，先在网页里调好再移植。

## 小智语音模块

`main/xiaozhi_audio/` 来自 [xiaozhi-esp32](https://github.com/78/xiaozhi-esp32)（MIT，版权声明见该目录 `LICENSE`，上游提交见 `UPSTREAM_COMMIT.txt`）。只保留了语音链路：ES8311/ES7210 驱动、AFE（回声消除、人声检测、唤醒词）、Opus 编解码、播放队列。我们做的改动：

- `audio_codec.h/.cc`：去掉对小智 `board.h` 的依赖。
- `audio_service.cc`：解码时用自己持有的 codec，不再找 `Board::GetInstance()`（行内有 `ai_pet:` 注释）。
- `protocol.h`：只保留 `AudioStreamPacket` 结构。
- `wake_words/custom_wake_word.h`：换成空实现（我们不带 MultiNet 模型）。

同步上游的语音改进时，对比这几个文件手动合并。
